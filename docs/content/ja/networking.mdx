## ネットワークを準備する

インターフェイスのアドレス、経路、到達可能なゲートウェイは別途設定します。Eleos が設定するのはファイアウォールと NAT のルールです。インターフェイス、DHCP、DNS サーバー、カーネルの転送設定は構成しません。以下の名前とアドレスは環境に合わせて置き換えてください。

IPv4 をルーティングする場合はカーネルの転送設定を確認し、有効にします。

```sh
sysctl net.ipv4.ip_forward
sudo sysctl -w net.ipv4.ip_forward=1
```

永続化にはディストリビューションの sysctl 設定を使います。Eleos はこの値を読み、0 なら警告するだけです。IPv6 のルーティングにも対応するカーネルの転送設定が必要です。

[初期設定](/ja/getting-started) のホスト用設定を出発点にし、`allowAllFwd: false` を維持したまま、以下の項目を **同じ YAML ファイル** に追加します。各例はホスト用の完全な設定ではありません。

## LAN から WAN への転送とマスカレード

```yaml
router:
  configAsRouter: true
  wanInterface: eth0
  privateNetworks: ["192.168.10.0/24"]
  lanInterfaces: [eth1]
```

| 項目 | 動作 |
| --- | --- |
| `configAsRouter` | ルーター用の転送ルールと、確立済み・関連接続の転送許可を有効にします。 |
| `wanInterface` | プライベートネットワークのマスカレードに使う送信インターフェイス。 |
| `privateNetworks` | WAN に出る際にマスカレードする送信元 CIDR。IPv6 CIDR では NAT66 のルールも生成できます。 |
| `lanInterfaces` | 転送通信を許可する受信インターフェイス。 |

**LAN の転送許可は広範囲です。** `lanInterfaces` のルールは指定したインターフェイスから来る転送通信を許可し、WAN 宛てや `privateNetworks` 内の送信元だけには限定しません。`privateNetworks` はマスカレードの条件であり、この転送許可の制限ではありません。ネットワーク分離の要件を確認してください。

## カスタムルートと DNS リダイレクト

```yaml
router:
  configAsRouter: true
  wanInterface: eth0
  privateNetworks: ["192.168.10.0/24"]
  lanInterfaces: [eth1]
  forceDNS: "192.168.10.1"
  customRoutes:
    - allowIP: "10.0.10.0/24"
      allowInterface: wg1
      allowDST: "192.168.10.0/24"
```

`customRoutes` は送信元 `allowIP`、受信インターフェイス `allowInterface`、宛先 `allowDST` のすべてに一致する転送を許可します。一致するマスカレードのルールも追加します。OS のルーティングテーブルに経路を追加する機能ではありません。

`forceDNS` は LAN インターフェイスから来る TCP/UDP の宛先ポート53を指定した IPv4 アドレスに転送します。既にその DNS 宛ての通信と、実装上のローカルホスト送信元の例外は対象外です。DNS リゾルバーの設定・起動や DNS-over-HTTPS/TLS の禁止は行いません。Eleos ホスト自身で DNS を動かす場合は、`ports` でも対象の LAN 送信元に TCP/UDP 53を許可してください。

## IPv4 ポート転送

上記の `router` 設定を残して確立済み・関連通信の転送を許可し、次を追加します。

```yaml
nat:
  - interface: eth0
    allowIP: "198.51.100.0/24"
    dstIP: "203.0.113.10"
    dstPort: "8443"
    proto: tcp
    natTo: "192.168.10.20:443"
```

この例は `eth0` で受信した `198.51.100.0/24` から `203.0.113.10` 宛ての TCP 8443を、`192.168.10.20:443` に変換します。公開側のアドレスは説明用です。実際にゲートウェイへ割り当て・経路設定されたアドレスを使ってください。転送先と戻りの経路が到達可能である必要があります。

| 項目 | 意味 |
| --- | --- |
| `interface` | DNAT の受信インターフェイス。対応する戻り通信の SNAT では送信インターフェイス。 |
| `allowIP` | 転送を許可する送信元 IP/CIDR。明示的に指定します。任意の IPv4 送信元なら `0.0.0.0/0`。 |
| `dstIP` | 変換前の宛先 IPv4 アドレス。CIDR は付けません。 |
| `dstPort` | 文字列で表した変換前の宛先ポート。 |
| `proto` | `tcp` または `udp` を明示します。 |
| `natTo` | `192.168.10.20:443` のような転送先 IPv4 アドレスとポート。 |

実装は受信インターフェイスと送信元に一致する forward の許可ルールを追加しますが、この許可は変換先や宛先ポートに限定されません。対応する SNAT は転送先の送信元アドレスと送信インターフェイスに一致します。構成に合わせて生成ルールを確認してください。

ルーターモードなしでも NAT ルールは生成できますが、その場合は forward に一般的な確立済み・関連接続の許可が追加されません。`allowAllFwd: false` では戻り通信が破棄される可能性があります。NAT だけの設定で転送環境が完成すると考えないでください。

## 確認する

```sh
sudo elctl apply
sudo nft list table inet eleos
```

別のクライアントから、転送設定・実際のインターフェイス名・経路・通信の往復を確認します。現在の実装で `forceDNS` と明示的な `nat` の転送先は IPv4 専用です。IPv6 のフィルタリングやプライベートネットワークのマスカレードとは別の機能です。
